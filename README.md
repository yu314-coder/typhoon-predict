# Typhoon Predict

Typhoon Predict is an experimental research implementation for causal
tropical-cyclone track, pressure, wind, and wind-structure forecasting over the
western Pacific. It is not an operational warning system and must not be used
for evacuation, aviation, maritime, emergency-management, or other
safety-critical decisions.

## Releases

| Release | Status | Scope |
|---|---|---|
| [Trackformer 1.1](https://github.com/yu314-coder/typhoon-predict/releases/tag/trackformer-1.1) | Frozen public baseline | Causal track, pressure, maximum wind, RMW, and ordered R34/R50/R64 radii |
| Trackformer 1.2.26 | Research baseline | Causal multi-task and physics-calibrated intensity experiments; not the public release |

and documentation. The Trackformer 1.1 checkpoint bundle is intentionally
stored as an asset of the GitHub Release rather than committed to the branch.
Download the release archive from the release page above and extract it at the
repository root if you need the frozen checkpoints.

Historical experiment names use the Trackformer1.0.x convention. They are
legacy research references, not current public releases.

## Model card summary

### Intended use

The project is intended for reproducible research on causal tropical-cyclone
forecasting and hindcast evaluation. It is useful for comparing feature
choices, lead-time errors, pressure-map structure, intensity curves, and
uncertainty generated by members of the same model.

It is not intended to replace a national meteorological service. A public
forecast must be checked against the latest official products and local
warnings.

### Model structure

Trackformer 1.1 combines:

1. A causal regional pressure-state module over the western Pacific.
2. Steering views from inner, deep-layer, ridge, trough, and jet levels.
3. Neural route experts that read observed storm history and current analysis
   patches.
4. Intensity and structure experts for maximum wind, central pressure, RMW,
   and four-quadrant R34/R50/R64 radii.
5. A temporal residual expert using only older analysis snapshots.

Radius outputs are constrained to be non-negative and ordered as
R34 >= R50 >= R64. The public model accepts compact arrays rather than raw
weather archives.

Trackformer 1.2.27 keeps the same causal source boundary and starts from the
frozen 1.2.26 physics-calibrated intensity path. Its candidate head predicts
lead-aware residual changes for maximum wind, central pressure, RMW, and
quadrant radii. It is intended to improve the current max-wind, pressure, and
radius errors without importing another agency's forecast.

### Data and training

The public baseline uses:

| Data | Role | Access |
|---|---|---|
| IBTrACS | Observed storm history, structure labels, training targets, and later verification | [NOAA/NCEI IBTrACS](https://www.ncei.noaa.gov/products/international-best-track-archive) |
| Historical atmospheric analysis | Current, -12 h, and -24 h pressure, height, and wind states for causal hindcasts | [NOAA Climate Forecast System](https://www.ncei.noaa.gov/products/weather-climate-models/climate-forecast-system) |
| Current atmospheric analysis | Latest available analysis whose valid time is no later than the issue time | [NOAA NOMADS](https://nomads.ncep.noaa.gov/) |
| Static geography | Land/sea mask, terrain, land-cover, coastal exposure, and location features | Public geographic data prepared into compact repository-side arrays |

CFSR and CFSv2 are not interchangeable. CFSR does not cover the full modern
period; later historical cases must use the matching CFSv2 or CDAS analysis
product selected in the preprocessing manifest. Every source and valid time
must be recorded before a hindcast is scored.

Training uses storm-disjoint chronological splits:

- training storms: first storm year through 2015;
- validation storms: 2016 through 2019;
- test storms: 2020 onward, held out until final scoring.

### Causal input boundary

At issue time, the model may use:

- observed IBTrACS storm history up to the issue time;
- current and past atmospheric analysis snapshots;
- current and past SST summaries;
- pressure-map, wind-flow, vertical-shear, and steering summaries;
- causal nearby-system interactions;
- static land, sea, terrain, coastline, and geographic features.

The model must not use:

- JMA, JTWC, ECMWF, GFS, GEFS, or another agency's forecast track;
- positive-lead forecast fields from any weather model;
- future observations or future IBTrACS labels as input;
- the realized future track, future intensity, or future radius.

Future observations are used only for chronological scoring after a forecast is
frozen. Official forecasts may be displayed as external comparisons, but they
are never model inputs.

### Evaluation

The frozen 1.2.26 causal physics-calibrated baseline scored on 9,994 untouched
test windows from first storm year >=2020:

| Metric at +120 h | Test error |
|---|---:|
| Central pressure MAE | 13.634 hPa |
| Mean radius MAE | 28.952 km |
| R34 MAE | 46.672 km |
| R50 MAE | 25.417 km |
| R64 MAE | 14.767 km |

These are baseline measurements, not a claim that 1.2.27 improves them.
Trackformer 1.2.27 will be promoted only after the validation split and the
untouched >=2020 test split are evaluated against this baseline. The quality
gate reports wind MAE, pressure MAE, RMW/radius MAE, bias by lead, radius-order
violations, and uncertainty coverage. A lower training error alone is not a
promotion criterion.

### Reproducible inference

After downloading the [Trackformer 1.1 release](https://github.com/yu314-coder/typhoon-predict/releases/tag/trackformer-1.1):

~~~bash
python -m pip install -r requirements.txt
~~~

The public Python loader accepts track=(9,54), field=(4,17,17), and an
optional history_field=(8,17,17) for older analysis patches. See
models/trackformer_1_1/manifest.json in the extracted release bundle and the
source modules:

- trackformer_1_1.py - public loader and route API;
- trackformer_1_1_route.py - causal pressure-state route;
- trackformer_1_1_intensity.py - intensity and wind-structure inference;
- trackformer_1_1_temporal.py - temporal expert architecture.

The release checkpoints are native PyTorch files. GGUF is not an appropriate
interchange format for this CNN/Transformer weather model; use the native
PyTorch bundle or another format only after numerical-parity testing.

### Requirements and limits

CPU inference requires Python 3.10 or newer, NumPy, PyTorch, and SciPy. A
modern machine with 8 GB RAM is a practical minimum; 16 GB or more is
preferable when decoding large analysis grids. Raw weather archives and
private credentials are not stored in this repository.

### Release documentation pattern

Each promoted release should include:

- a versioned model card and source-policy manifest;
- a reproducible checkpoint archive attached to the same GitHub repository
  release;
- training, validation, and untouched test metrics;
- a clear data boundary and retrieval instructions;
- case maps and intensity/structure plots;
- explicit limitations and a statement that official forecasts are external
  comparisons, never model inputs.
